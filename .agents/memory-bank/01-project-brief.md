# Проект: MCP-сервер Corrective RAG (краткая сводка)

## Назначение

MCP-сервер, который превращает локальную папку с документами в поисковую базу знаний.
Разработчик подключает сервер к IDE (Copilot, Claude и др.), индексирует документы и задаёт
вопросы — AI в IDE получает ответы на основе содержимого файлов.

Внутри сервера — Corrective RAG-пайплайн с **локальной LLM через Ollama** (без платных API)
и эмбеддингами **multilingual-e5-small** (ONNX, 384 измерения).

## Ключевые технологии

| Технология | Роль |
|---|---|
| .NET 10 / ASP.NET Core | Хост MCP-сервера (HTTP Streamable, Stateless) |
| ModelContextProtocol.AspNetCore 2.1.0 | Официальный C# SDK MCP |
| SQLite + FTS5 | Хранение текста, векторов, полнотекстовый индекс BM25 |
| Microsoft.ML.OnnxRuntime 1.30.0 | Инференс модели эмбеддингов |
| Tokenizers.HuggingFace 3.23.1 | Токенизация (tokenizer.json модели) |
| Ollama (OpenAI-совместимый /v1) | Грейдинг релевантности чанков + расширение запроса |
| MediatR 14.2.0 | Запросы/обработчики (Request и Handler рядом) |
| Serilog | Логирование: stdout + файл, от уровня Information |

## Бизнес-правила

- **Индексация**: файлы сканируются по glob-паттерну, текст делится на чанки
  (480 токенов, перекрытие 20), каждый чанк → вектор (lowercase + `passage: `, mean pooling, L2).
  Неизменённые файлы пропускаются по SHA-256; изменённые — переиндексируются полностью.
- **Поиск**: гибридный — BM25 (FTS5) + векторный → Reciprocal Rank Fusion (k=60) → топ-10.
- **Grade Chunks**: локальная LLM оценивает релевантность каждого чанка (yes/no);
  если релевантных < 3 (настраивается), запрос расширяется через Ollama и поиск повторяется
  (до 2 раз). Финальный ответ формирует **агент-хост**, MCP возвращает JSON с чанками и метаданными.

## Решения, принятые с пользователем

- Хеш содержимого — **SHA-256** (в исходном ТЗ была путаница MD5/SHA-256).
- БД — `Resources/vectorDb.db`, путь из `appsettings.json` (`Database:Path`), переопределяется env.
- Ollama — `Ollama__BaseUrl=http://localhost:11434/v1`, модель `qwen2.5:3b` (из конфига).
- `find_relevant_docs` — без LLM; `ask_question` — с грейдингом/расширением, но БЕЗ генерации ответа.
- FTS5 синхронизируется триггерами на INSERT/DELETE по таблице `Chunks` (не на удалении эмбеддинга).
