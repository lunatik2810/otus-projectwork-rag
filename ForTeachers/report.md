Для решения задачи сначала разбиралась, что вообще нужно сделать. 
Не сразу было понятно, что требуется. Понятно, что RAG, но как его сделать, было не очевидно. 
Общее знание, что это такое было, а на уровне векторов не было. 
Немного запутанное ТЗ было для меня, пришлось разбираться. 
Загрузила задание в ChatGPT, чтобы понять, что требуется, спрашивала по некоторым шагам.

## Как это сделать на .net

С учетом того, что на .net нет функций, которые есть в LangChain и LangGraph, пришлось искать альтернативы.
Первый вариант был с использованием VectorRAG.Net. 
Сразу посмотрела, что для коммерчиского использования, но не думала что для учебных целей они тоже потребуют лицензии. VectorRAG.Net давал из коробки многие вещи.

Пока с ним разбиралась, сразу разобралась с Embedding, т.к. VectorRAG.Net все равно нужно их подавать. 
Чтобы их получить, тоже было несколько вариантов, хотелось локального решения. Остановилась на ONNX-моделе multilingual-e5-small. Она не много весит. Качала модель из https://huggingface.co/intfloat/multilingual-e5-small/tree/main/onnx?utm_source=chatgpt.com

После отказа от VectorRAG.Net, решила не использовать дополнительные сборки, сервисы, а реализовать самой через SQLite.
Причем SQLite поддерживает векторные поля, что было очень удобно, а также быстрый поиск по словам (BM25) через виртуальную полнотекстовую таблицу FTS5. Осталось придумать, как делить на чанки. Решила сделать такую логику: разделить все на части по [.!?...], чтобы потом был пробел и заглавная буква. Конец предложения или перевод на новую строку. Дальше для этих частей посчитала токены, а потом собирала чанк, чтобы не превышало 480 токенов (модельmultilingual-e5-small работает нормально только при менее 500).

Попробовала сделать на тестовом проекте, чтобы понять, как это работает. Первую чать реализовывала там, потом попросила ИИ составить промпт для переноса, но как-то плохо получилось, в итоге сама писала [02-prompt-first-plan.md](Prompts/02-prompt-first-plan.md) 

При тестировании интересно было посмотреть, как происходит поиск, да и гибридный поиск интересный. Был тест, где векторный поиск нашел слово из запроса в другом склонении, а почему-то по BM25 ничего не нашлось (оно правда было в части email, но все равно). 

После тестирования в xUnit запустила проект под отладкой, попробовала в трех агентах: GitHub Copilot(Visual Studio 2026), GitHub Copilot (VS Code) и OpenCode. Прошла все этапы.

После этого уже финальная проверка была в docker.

# Описание использованных инструментов и моделей

Подробнее в memory-bank. Попросила подготовить данные Агента, ниже краткая сводка:

## Модели

multilingual-e5-small (ONNX, 384 измерения)	- Эмбеддинги текста. Локальная, скачана с Hugging Face (intfloat/multilingual-e5-small/onnx). Инференс через ONNX Runtime; входы input_ids, attention_mask, token_type_ids; выход — mean pooling по маске внимания → L2-нормализация. Требует lowercase + префиксы passage: / query: ; работает стабильно при длине до ~500 токенов (чанки по 480 токенов)

qwen2.5:3b (локальная LLM через Ollama, http://localhost:11434/v1, OpenAI-совместимый API) - 	Грейдинг релевантности чанков (yes/no) и расширение запроса (QueryExpander) в Corrective RAG

## Инструменты и технологии (.NET)

.NET 10 / ASP.NET Core - Хост MCP-сервера (HTTP Streamable, Stateless)

ModelContextProtocol.AspNetCore 2.1.0 - Официальный C# SDK для MCP-серверов

SQLite + FTS5 - Хранение текста, векторов; полнотекстовый индекс BM25 (синхронизация триггерами)

Microsoft.ML.OnnxRuntime 1.30.0 - Инференс модели эмбеддингов

Tokenizers.HuggingFace 3.23.1 - Токенизация через tokenizer.json модели

MediatR 14.2.0 - Запросы/обработчики (Request и Handler рядом)

Serilog - Логирование: stdout + файл, от уровня Information

Docker / docker-compose - Финальная проверка работы сервера в контейнере

xUnit - Модульные тесты (тесты инструментов MCP, папка Tests/testProjectMCP-RAG)
