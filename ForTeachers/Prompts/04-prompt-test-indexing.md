## 3. Ход работы и замечания пользователя (диалог)

### 3.1 Первая сборка — стоп-ошибки

- **NETSDK1151**: основной проект self-contained (single-file publish) — неавтономный
  тестовый проект не может на него ссылаться. Сначала был добавлен RID/self-contained-хак
  в тестовый проект — не сработало (нет ref-сборки `obj\...\win-x64\ref\`).
  **Решение:** `SelfContained`/`PublishSelfContained`/`PublishSingleFile` вынесены из
  [`otus-projectwork-rag.csproj`](../../otus-projectwork-rag.csproj) в параметры
  `dotnet publish`; добавлены `ProduceReferenceAssembly=true`.
- **init-свойства опций**: `services.Configure<T>(o => o.X = ...)` не компилируется
  (`DatabaseOptions.Path` и др. объявлены как `init`). Перегрузки `Configure(T options)`
  в этой версии нет.
  **Решение:** регистрация через `Options.Create(new T { ... })` в
  [`RagTestHost.cs`](../../Tests/testProjectMCP-RAG/RagTestHost.cs).
- **Дубли атрибутов сборки + потеря `Fact`/`Microsoft.Testing`**: основной проект
  default-glob'ом `**/*.cs` захватывал исходники тестов И сгенерированные файлы из
  `Tests\testProjectMCP-RAG\obj` (два AssemblyInfo → «повторяющийся атрибут»,
  `XunitAutoGeneratedEntryPoint`, `SelfRegisteredExtensions`).
  **Решение:** `<Compile/Content/EmbeddedResource/None Remove="Tests\**" />` в основном csproj.

### 3.2 Microsoft Testing Platform (MTP) — обязателен на .NET 10 SDK

Реальная ошибка из CLI: `Testing with VSTest target is no longer supported by
Microsoft.Testing.Platform on .NET 10 SDK and later`.

**Решение (по документации aka.ms/dotnet-test-mtp-error):**

- создан [`global.json`](../../global.json) с `"test": { "runner": "Microsoft.Testing.Platform" }`;
- удалён VSTest-адаптер `xunit.runner.visualstudio` и свойство
  `TestingPlatformDotnetTestSupport` (legacy-режим, в MTP 2.x запрещён);
- добавлено `UseMicrosoftTestingPlatformRunner=true` — переключает сгенерированную
  точку входа xunit.v3 с «In-Process Console Runner» на «Microsoft.Testing.Platform v2 Runner»
  (подтверждено баннером при запуске);
- после отказа от `Microsoft.NET.Test.Sdk` потребовалось явно
  `<OutputType>Exe</OutputType>` + `<UseAppHost>true</UseAppHost>` (требование xunit.v3);
- удалены VSTest-пакеты `Microsoft.NET.Test.Sdk` и `coverlet.collector` (смешение
  VSTest и MTP в одном проекте официально не поддерживается), добавлена прямая ссылка
  `Microsoft.Testing.Platform`.

### 3.3 Замечания пользователя по ходу сессии

1. **«Я сама буду запускать тесты»** → команды `dotnet test` выполнял пользователь;
   затем разрешил запускать самостоятельно.
2. **xUnit1051**: «Calls to methods which accept CancellationToken should use
   TestContext.Current.CancellationToken» → во все отменяемые вызовы передан
   `TestContext.Current.CancellationToken`.
3. **«В чём разница двух тестов? Нет прямого обращения к Tool»** → разъяснено и
   зафиксировано комментариями: вариант A вызывает сам `[McpServerTool]`-метод
   `RagTools.IndexFolder` (обёртка с логированием/таймингом), вариант B повторяет
   внутреннюю строку `mediator.Send(new IndexFolderRequest(...))` — поэтому и имя другое.
4. **«Названия методов никогда не делай на русском языке»** → имена методов
   возвращены на английский (комментарии — русские, по правилу agent.md).
5. **«Не создавай файлы в Local/Temp (AppData)»** → временные документы и БД теперь
   создаются в `Tests\testProjectMCP-RAG\.rag-test-tmp` (уникальная сессионная
   подпапка на каждый хост), удаляются в `Dispose`.
6. **«После теста не удалил все файлы из .rag-test-tmp»** → найдена причина:
   Microsoft.Data.Sqlite пулирует соединения (`Pooling` по умолчанию), файл БД остаётся
   заблокирован до выхода из процесса. **Решение:** `SqliteConnection.ClearAllPools()`
   в `Dispose` + снятие атрибутов + ретраи удаления + удаление корня `.rag-test-tmp`
   при пустоте. После правки: `CLEAN: no .rag-test-tmp after run`.
